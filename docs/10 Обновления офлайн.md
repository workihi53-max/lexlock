# Обновления без интернета: подписанный офлайн-канал

Отвечает на главный вопрос критики с «Экватора»: **«как будут доставляться
обновления, если агент не имеет доступа в сеть и данные не должны утечь»**.

Короткий ответ: **обновления не доставляет само приложение.** Их скачивает человек
(браузером, с флешки, с корпоративного портала) как обычный файл `*.lexlock`, а
приложение проверяет и применяет его полностью офлайн — по встроенному открытому
ключу. Это стандартная схема air-gapped-поставки (так же обновляются HSM,
криптокошельки, медицинское и военное ПО).

## Почему это решает противоречие

| Ограничение | Как снимается |
|---|---|
| Агент не имеет доступа в сеть | Сеть нужна только человеку, скачивающему файл обновления — вне приложения |
| Данные не должны утечь | Агент и Ollama работают на loopback (`enforce_offline`), канал обновлений — односторонний: только ввод файла, никогда вывод данных |
| Подпись и целостность | Пакет подписан Ed25519, каждый файл сверяется по SHA-256 |
| Откат | Старые файлы сохраняются в `.lexlock_backup/<version>/` |
| Повторный запуск | Версия пишется в `.lexlock_update`, повторное применение той же версии отклоняется |

## Формат пакета `*.lexlock`

Обычный zip-архив:

```
manifest.json   {"version": "0.2.4", "files": {"lexlock/agent.py": "<sha256>", ...}}
signature       Ed25519-подпись над байтами manifest.json (raw)
payload/...     файлы для замены, пути относительно корня проекта
```

Проверка двухступенчатая: сначала подпись манифеста, затем sha256 каждого файла.
Только после обеих проверок файлы применяются.

## Кто что делает

- **Вендор** (`scripts/make_update.py`) — собирает и подписывает пакет закрытым
  ключом. Закрытый ключ хранится только у вендора и в пакет не попадает.
- **Клиент** (`lexlock/updater.py`) — проверяет подпись встроенным открытым ключом
  и применяет пакет офлайн. Открытый ключ не секретен, он просто фиксирует
  доверие к вендору.

```bash
# вендор: сгенерировать пару ключей (один раз)
python scripts/make_update.py --gen-key --key update_key.pem

# вендор: собрать и подписать обновление
python scripts/make_update.py --private-key update_key.pem \
    --version 0.2.4 --out dist/lexlock-0.2.4.lexlock --note "исправления"

# клиент: проверить и применить (офлайн, отдельной командой, не из приложения)
.venv/bin/python -c "from lexlock import updater; print(updater.apply_bundle('lexlock-0.2.4.lexlock', '.'))"
```

## Что обновляется, а что нет

- Обновляются код (`lexlock/`, `app/`), шаблоны (`templates/`), скрипты, промпты.
- Модель Ollama обновляется штатным `ollama pull` — тоже офлайн, так как Ollama
  локальна; либо новой версией пакета, если модель поставляется в нём.
- Документы клиента (`workspace/`) обновление **не трогает** — они вне белого
  списка `INCLUDE`.

## Связь с монетизацией

Это реализация «варианта 3» из [[07 Монетизация и обновления]]: ядро разовой
покупкой живёт офлайн, а подписной канал — это и есть подписанные `*.lexlock`
(новые шаблоны, чек-листы, промпты, обновлённая модель). Канал изолирован и
односторонний, поэтому сам не создаёт риск утечки.

## Кибербезопасность

- Сеть: `lexlock/offline.py` патчит `socket` — наружу не уходит ни один запрос.
- Обновления: подпись + контрольные суммы, без доверия «на лету».
- Аудит: `lexlock/audit.py` пишет журнал действий агента с hash-цепочкой —
  любую правку журнала видно через `audit.verify()`.
